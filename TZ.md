Перед собеседованием необходимо выполнить тестовое задание
Тестовое задание состоит из 3 обязательных задач. Все три задачи нужно выполнить – оценка идёт по совокупности результатов и по подходу к решению. Ориентировочное время выполнения – 5-6 часов суммарно.

Можно использовать документацию, AI-ассистентов, поисковики – оцениваем результат и подход. Если что-то непонятно или возникли технические проблемы – напишите об этом.

Задача 1. Вайбкодинг с Claude Code: веб-утилита
Разработайте небольшую веб-утилиту с помощью Claude Code. Тематика – на ваш выбор в рамках практической пользы (примеры: калькулятор расчёта дозировки, конвертер единиц, мини-форма обратной связи с валидацией, утилита для генерации/проверки промокодов и т.п.).
Требования:
• Полноценная веб-страница (HTML + CSS + JS) или приложение на любом подходящем стеке (например, FastAPI/Flask + фронтенд)
• Минимум одна нетривиальная логика на стороне клиента или сервера – не просто статическая страница
• Код должен быть читаемым и структурированным, не одной портянкой
Что предоставить:
• Исходный код проекта – в виде архива или ссылки на репозиторий (GitHub, GitLab и т.п.)
• Описание процесса работы с Claude Code: какие промпты использовали, что AI сделал сразу, что пришлось доработать руками и почему. Достаточно 5–10 предложений, можно с примерами ключевых промптов
• По возможности – развёрнутая рабочая версия (например, на GitHub Pages, Vercel, Netlify или локально с инструкцией по запуску), чтобы можно было проверить «снаружи»

Задача 2. Python-скрипт с обращением к внешнему API + Docker
Напишите Python-скрипт, который обращается к публичному внешнему API на ваш выбор (примеры: API ЦБ РФ по курсам валют, OpenWeatherMap, GitHub API, любой другой открытый API без сложной авторизации), обрабатывает полученные данные и выводит структурированный результат.
Требования к скрипту:
• Корректная работа с HTTP-запросами (requests или аналог) и обработка ответа в JSON
• Простая, но осмысленная обработка данных – не просто вывод сырого ответа. Например: фильтрация, агрегация, сортировка, расчёт производных значений
• Базовая обработка ошибок (недоступность API, неожиданный формат ответа)
• Читаемый вывод в консоль или сохранение результата в файл (CSV/JSON – на выбор)
Дополнительно:
• Dockerfile для запуска скрипта в контейнере
• Файл зависимостей (requirements.txt)
• Краткая инструкция по сборке и запуску (3–4 команды)
Что предоставить:
• Исходный код скрипта (.py), Dockerfile, requirements.txt – в виде архива или ссылки на репозиторий
• Инструкция по запуску
• Пример вывода работы скрипта (скриншот консоли или сохранённый файл с результатом)

Задача 3. Apps Script + внешний API в Google Таблице
Напишите Apps Script для Google Таблицы, который обращается к внешнему API (можно тот же, что и в Задаче 2, можно другой) и записывает обработанные данные в таблицу.

Требования:
• Скрипт запускается по триггеру – на ваш выбор (по расписанию, по кнопке/меню в таблице, по событию редактирования)
• Корректная работа с UrlFetchApp для HTTP-запроса
• Парсинг JSON-ответа и запись данных в нужные столбцы в структурированном виде
• Базовая обработка ошибок (API недоступен, ответ некорректен) – запись статуса/ошибки в отдельную ячейку или столбец
• Код оформлен в виде минимум одной функции с понятным названием и комментариями к ключевым шагам

Что предоставить:
• Код Apps Script (.gs или текстом в составе архива/документа)
• Ссылка на Google Таблицу с открытым доступом для просмотра – чтобы можно было увидеть результат работы скрипта и сам код
• Краткое описание: какой триггер использовали, какой API подключали, какая логика обработки

Формат сдачи
Соберите всё в один документ (Google Docs или текстовый файл) со следующим содержимым:
• Исходные коды и файловые структуры проектов – в виде архива (.zip) или ссылки на репозиторий (GitHub, GitLab и т.п.), на ваше усмотрение
• Ссылки на рабочие развёрнутые версии (где возможно)
• Ссылка на Google Таблицу из Задачи 3
• Краткие пояснения по каждой задаче
• Затраченное время по каждой задаче
Исходные коды и структура файлов проектов обязательны – это необходимо для внешней проверки решений.

Что оцениваем
• Рабочий результат по каждой из трёх задач
• Качество и читаемость кода, разумная структура проектов
• Осмысленность использования AI-инструментов (особенно в Задаче 1) – не просто «сгенерировал и сдал», а понимание того, что было сделано и почему
• Подход к работе с API: обработка ошибок, корректный парсинг данных, продуманная логика
• Аккуратность в деталях: понятные комментарии, нормальные имена переменных, осмысленная структура файловs
