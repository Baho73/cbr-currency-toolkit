## Задача 1 — Веб-конвертер валют (FastAPI)

**Что это:** веб-утилита для конвертации сумм между валютами по официальным
курсам ЦБ РФ. Асинхронный бэкенд на FastAPI + фронтенд на HTML/CSS/JS.

**Нетривиальная логика:** кросс-конвертация суммы из любой валюты в любую
через рубль с корректным учётом номинала (например, японская иена котируется
за 100 единиц). Расчёт ведётся в `Decimal` для денежной точности.

**Устойчивость (продакшн-подход):**
- Асинхронный ввод-вывод: `httpx.AsyncClient`, async-роуты FastAPI.
- HTTP-клиент с retry и экспоненциальным backoff, таймаутом.
- TTL-кэш курсов с защитой от гонок (`asyncio.Lock`, single-flight) — внешний
  API не дёргается на каждый запрос (ЦБ обновляет курс раз в сутки).
- Иерархия исключений с трансляцией в HTTP-коды (502/400/422).
- ООП: каждый модуль — класс/сервис с зафиксированным контрактом.
- 33 автотеста с замоканным HTTP (`respx`), реальная сеть в тестах не нужна.

**Запуск:** `docker build -t currency-web . && docker run -p 8000:8000 currency-web`
→ <http://localhost:8000>. Подробно — `task1-currency-web/README.md`.

**Деплой:** файл `task1-currency-web/render.yaml` описывает деплой на Render.com
(free tier, Docker). Smoke-тест локально пройден: 55 валют, конвертация
100 USD → 7312.75 ₽ по реальному курсу.

**Затраченное время:** ≈ 2 ч 30 мин.

## Задача 2 — Async CLI-скрипт + Docker

**Что это:** Python-утилита командной строки: асинхронно загружает курсы валют,
считает производные значения и выводит структурированный отчёт с экспортом.

**Осмысленная обработка данных:** по каждой валюте — абсолютная суточная дельта
и процент изменения; сортировка по волатильности; топ-N движений за сутки;
агрегированная сводка (среднее изменение, самая укрепившаяся/ослабшая валюта).

**Устойчивость:**
- Асинхронный HTTP-клиент (`httpx.AsyncClient`) с retry и backoff.
- Базовая обработка ошибок: недоступность API → понятное сообщение и код
  возврата 1; некорректный формат ответа → код 2; иерархия исключений.
- Строгая валидация структуры JSON-ответа.
- Экспорт результата в CSV или JSON; читаемая таблица в консоль.
- 32 автотеста с замоканным HTTP.

**Запуск:**
```
docker build -t cbr-cli .
docker run --rm -v "${PWD}/output:/app/output" cbr-cli --format csv --top 5
```
Подробно — `task2-cbr-cli/README.md`. Пример вывода — `task2-cbr-cli/examples/`.

**Затраченное время:** ≈ 1 ч 45 мин.

## Задача 3 — Google Apps Script

**Что это:** Apps Script, который по триггеру обращается к API ЦБ РФ и
записывает обработанные курсы в Google Таблицу.

- **Триггер:** кастомное меню «Курсы ЦБ РФ → Обновить курсы» (simple-триггер
  `onOpen`); опционально — time-driven триггер раз в сутки.
- **API:** тот же `cbr-xml-daily.ru`, запрос через `UrlFetchApp`.
- **Логика обработки:** парсинг JSON, расчёт суточного изменения (абсолютного
  и в %), сортировка по коду, пакетная запись в столбцы.
- **Обработка ошибок:** `UrlFetchApp` с `muteHttpExceptions`, ручная проверка
  кода ответа; любой сбой пишется в ячейку статуса `A1` (красным) — ошибка
  видна пользователю, скрипт не падает «тихо».
- **Структура:** 4 файла `.gs` (`Config`, `CbrService`, `SheetWriter`, `Main`)
  с ООП-классами и комментариями к ключевым шагам.

**Установка и доступ:** инструкция в `task3-apps-script/README.md`.

**Затраченное время:** ≈ 1 ч 00 мин.

## Описание процесса работы с Claude Code (Задача 1 и весь проект)

Проект целиком разработан с помощью Claude Code по методологии **GRACE**
(контракт-ориентированная разработка: сначала требования и архитектура,
затем код под контракты, с обязательной верификацией).

**Ключевые этапы и промпты:**
1. *Брейншторминг* — уточнение предметной области и стека (выбраны курсы ЦБ РФ
   и FastAPI как стек, демонстрирующий ООП и асинхронность).
2. *Планирование* — Claude спроектировал архитектуру из 21 модуля с контрактами
   (`docs/development-plan.xml`), графом зависимостей и планом верификации.
3. *Пошаговая реализация* — модуль за модулем: код с контрактом → тесты →
   прогон `pytest` → коммит. История git содержит один коммит на модуль.

**Что AI сделал сразу:** корректную модульную архитектуру, async-клиент с
retry, конвертер с учётом номинала, FastAPI-приложение с lifespan и DI,
фронтенд на ООП-классах, полное покрытие тестами (65 тестов).

**Что пришлось доработать после проверки (примеры):**
- *Кодировка консоли:* при первом живом прогоне CLI на Windows символы `₽`/`▲`
  роняли вывод (`UnicodeEncodeError`, cp1251). Добавлена принудительная
  перенастройка stdout/stderr в UTF-8 в точке входа процесса (v1.0.1).
- *Чистота GRACE-разметки:* линтер выявил расхождения (некорректные значения
  `ROLE`, переменная `logger` трактовалась как публичный экспорт, отсутствие
  `CHANGE_SUMMARY` в тестовых файлах) — разметка приведена к 0 ошибок.
- *Корректность парсинга:* парсер ответа API вынесен в доменный слой с явной
  валидацией и единым исключением `CbrResponseError` вместо случайных
  `KeyError`/`TypeError`.

Каждое изменение сопровождалось прогоном тестов и проверкой линтером — правки
вносились осознанно, а не «сгенерировал и сдал».
